## Overview

Word Lookup is a select-a-word, get-an-instant-translation-card tool for people reading dense
technical or academic English on their phone in a language that isn't their first. The audience
is students and professionals working through PDFs, papers, and reports who need a definition and
translation without breaking reading flow. The product has to earn its keep in under a second of
attention: **instant, unobtrusive, precise** — a floating card that appears exactly where the eye
already is, says exactly what's needed, and gets out of the way.

**Round 6 (this palette):** deliberately diverged from the companion desktop app's violet system to
a Dieter Rams-influenced monochrome direction, at the user's explicit request. The two apps no
longer share a palette - the desktop (`kannada_lookup`) keeps its own violet DESIGN.md unchanged.
They still share the underlying product shape (instant, unobtrusive, precise) and the two type
families below; only the color system split. Don't "fix" this back into sync without being asked -
it's intentional, not drift.

## Colors

Cool-neutral greys - chosen to sit correctly beneath the lookup card's own unchanged
`#FDFDFE → #EDF2FB` gradient rather than fight it - plus exactly one signal accent, reserved for
on/active state and nothing else. Light and dark are both real, wired themes (`Theme.kt`'s
`lightColorScheme`/`darkColorScheme`), not a light system with unused dark tokens sitting beside it.

- **Primary (#16181C / dark #E9EBEF):** Headline and body text, and the fill of the primary button
  and the home screen's summary card - the darkest thing on screen is the primary action, no
  accent hue needed to say "tap this." (Named `primary` for schema continuity with the palette
  this replaces, even though - unlike the old violet `tertiary` - it is not itself the accent;
  `signal` is. See the button/summary-card/section-card-title components below for how `primary`,
  `secondary`, and `tertiary` are actually used.)
- **Secondary (#5F636B / dark #9298A1):** Supporting text - captions, metadata, descriptions,
  section-card eyebrow labels.
- **Tertiary (#9298A1 / dark #666B74):** Placeholder text, the least emphasized tier.
- **Signal (#C4440B / dark #E86A2A):** The *only* color that means "this is on" - the enabled
  switch's checked track, a granted permission's status dot. It appears nowhere else; an accent
  that shows up everywhere is decoration, not signal. Clears WCAG AA both as text on white
  (5.03:1) and as a fill under white text - strictly better than the palette it replaces, whose
  `#7150F0` measured 4.11:1 as button text and needed a separate darker substitute in code.
- **Brand-identity (#16181C):** The launcher icon, Quick Settings tile, and in-app mark all share
  this ink ground - see "Language-reactive icon" below.
- **Neutral (#FFFFFF / dark #121316) / Surface (#FFFFFF / dark #1A1C20) / Sunken (#E8EAEE / dark
  #24272C):** Background, card surface, and the recessed fill (segmented-control track, note
  panels, and - round 7 - input fields). Neutral and Surface are now the same value in light mode;
  since round 7 a tile's edge is a shadow, not a background/surface value contrast, so the two no
  longer need to differ.
- **Outline (#DDE0E6 / dark #2E3238) / Outline-strong (#C4C9D2 / dark #414650):** Round 7 narrowed
  these to row-dividers inside a tile (e.g. between the two Access permission rows) and the
  segmented control's selected-key edge. A tile's own boundary is a soft shadow now, not a
  hairline - see "Tiles have shadow, not outline" under Components.
- **Error (#8C2A18 / dark #E5A08F):** Reserved for the lookup card's failure-state text only -
  never a button, icon, or destructive-action color elsewhere in the system.
- **Card gradient (#FDFDFE → #EDF2FB):** The floating lookup card's own subtle top-to-bottom wash -
  unchanged since v0.1.0, and deliberately untouched by this round's repalette.
- **Word-text (#1A1A1A) / Translation-text (#111111):** The two headline weights inside the card -
  translation is fractionally darker than the headword, so the eye lands there first.
- **Pos-text (#8A8F9C) / Meaning-text (#333333) / Synonyms-text (#6A6A6A) / Example-text
  (#555555):** A deliberate ladder of four grays, darkest to lightest in reading priority -
  meaning first, then example, then synonyms, then the part-of-speech tag last. This ladder was
  already monochrome before this round; nothing about it needed to change, which is part of why
  the lookup card itself was left untouched.

### Language-reactive icon

Every one of the 26 supported languages (`data/Languages.kt`) gets its own launcher icon, Quick
Settings tile icon, and in-app brand mark - ink ground, that language's own script glyph in white.
Switching the target language switches all three live. Generated by `tools/gen_lang_icons.py`
(vector outlines extracted from real fonts, not hand-drawn) for the 26 launcher icons; the tile and
in-app mark render their glyph live on-device instead, since those don't need to be static
resources. One exception: Indonesian's glyph (Balinese "ᬅ") has no real font outline available on
the machine that generated the launcher assets - every font that claims cmap coverage for it
renders an empty box - so the *launcher icon only* falls back to the Latin text "ID"; the tile and
in-app mark keep the real glyph, since Android's own font stack renders it live.

## Typography

Two families split by script. **Poppins** (round 7 - bundled as real `res/font/` files, SIL Open
Font License) for every Latin-script UI element (headlines, buttons, labels, meanings, English
examples); **Noto Sans Kannada** for anything rendered in the target language itself, via Android's
own font fallback rather than a bundled file - Poppins has no glyphs for Kannada/Devanagari/CJK/etc,
so those characters fall through to the system's script font automatically. This is a change from
the desktop app's own DESIGN.md, which still specifies Inter - the two already diverged on color in
round 6 and now diverge on the Latin typeface too; not something to "fix" back into sync without
being asked, same rule as the palette split. Native-script text gets visibly larger and looser
line-height (1.7–1.75 vs. 1.5–1.55 for the Latin family) — Kannada glyphs read smaller than Latin
ones at the same point size, so the size bump keeps perceived weight equal, not literal size equal.
Google Sans (Product Sans) was the first choice but isn't an option: it's Google's proprietary
internal typeface, never published to Google Fonts, not licensed for third-party bundling - Poppins
was chosen as the closest legitimately-available look-alike (geometric, rounded terminals).

- **Display-lg:** The "Word Lookup" title on the home screen. Used exactly once per screen.
- **Headline-md:** Section card titles ("Permissions", "Trigger"), the headword in the register.
- **Body-lg (native):** The translation itself, inside the lookup card - the single most
  important word on screen, so it gets the native family's largest, most generous size.
- **Body-md:** Meanings and general body copy - the default reading size.
- **Body-sm:** Synonyms, examples, captions, and the permission-row descriptions - present but
  clearly secondary.
- **Body-native (smaller):** The native-language example sentence under the translation - big
  enough to read comfortably, small enough not to compete with the translation above it.
- **Label-md:** Button text.
- **Label-sm:** Uppercase micro-labels - section-card eyebrows, the "ON"/"OFF" status word beside
  a permission row, the onboarding step count. No longer reserved/unused as of round 6.

## Layout

An 8px base grid throughout (`spacing.*`), mapped 1:1 to `dp` in the Compose implementation. Round
7 moved Home to an explicit `Arrangement.spacedBy(16dp)` stack instead of per-tile margins, so the
gap between tiles is even regardless of what each one contains internally - the previous
margin-collapsing approach looked uneven next to the summary card's larger padding.

Four recurring shapes: the **home screen** is Header, the ink summary card, the
"How it opens" section card, then two navigation cards (Word register, Settings); the **Settings
screen** (round 7, new - see "The settings hub" below) holds everything that used to crowd Home;
the **lookup card** is a floating, fixed-width (320dp) overlay anchored to the selection, never
full-width; the **register** is a scrolling stack of lookup cards (see "The word register is the
lookup card" below), `spacing.sm` apart, not a flat divided list.

## Shapes

Corner radius scales with how "contained" an element feels, unchanged since before round 6: cards
use `rounded.xl` (16dp) - soft enough to read as a floating object, not a hard-edged panel. Buttons
and inputs use `rounded.md` (8dp) - present but restrained, since a button repeated a dozen times
on one screen shouldn't compete visually with the cards holding it. `rounded.full` is reserved for
the status dot's circle and nothing else - not a pill/chip shape any more (see Components below).
Unchanged by round 7's border-to-shadow move - that round touched *depth*, not *shape*.

## Components

**Buttons.** One filled primary style (ink fill, white text) for the single most important action
per screen - "Continue" on setup. Everything else, including permission "Open Settings" actions,
is a secondary (outline or text) button. A screen with two filled buttons is a bug, not a design
choice - it means the hierarchy wasn't decided.

**Section cards.** Every card that groups settings (Access and the banking-pause card on Settings,
"How it opens" on Home) shares one shape, one fill, one padding. They are containers for
*settings*, not for *results* - the lookup card is deliberately a different shape (a floating
gradient card, not a flat white one) so a user never confuses "a card I'm configuring" with "a
card telling me an answer." The home screen's summary card is the one exception - an ink gradient
with a matching glow, not a border - reserved for the single most important fact on the screen
(the active language), never reused for an ordinary settings group.

**The settings hub (round 7).** Access, the banking-pause action, and the language/API-key/App-Info/
tile-add actions used to sit loose on Home, all at once. They now live one tap away, behind a
"Settings" navigation card next to "Word register." Home's job stays narrow: show whether the app
is running, what language it's set to, and how lookups trigger - not every knob the app has.

**Pause for banking.** A real OS action, not a preference: it calls
`AccessibilityService.disableSelf()`, which genuinely removes the app from
`enabled_accessibility_services` - unlike the master switch or the Quick Settings tile, which only
change flags this app reads itself and are invisible to a banking app's fraud SDK. Android will not
let an app re-enable its own accessibility service, so the card states that plainly rather than
implying a second tap undoes the first.

**Tiles have shadow, not outline (round 7).** Section cards, navigation cards, register entries,
and text fields dropped their 1px hairline border in favour of a soft shadow - `outline` no longer
means "this is a tile's edge" anywhere in the system. It still means "this is a divider between
rows inside one tile" (the rule between the two Access permission rows) and "this is the segmented
control's selected-key edge" - both narrower, intentional survivals, not oversights.

**The lookup card.** The product's single most important surface, and the one part of this system
untouched by round 6's repalette - see its own five-color ladder above. Headword and translation
are both headline-weight; everything else (part of speech, meaning, synonyms, example) is body or
smaller. It never has more than one CTA (dismiss-by-tap on the card itself) - no button chrome
inside it, because it needs to disappear as easily as it appeared.

**The word register is the lookup card.** Since round 6, each saved lookup renders as the exact
same composable the floating card uses (`LookupResultBody`), not a second, differently-styled
layout - a saved word and a live lookup are the same object, so they look like the same object.
The register adds only what the popup has no room for: a quiet delete glyph and a language/date
line, both drawn in the card's own `pos-text` grey so the addition reads as part of the card's
ladder, not as an import of app-theme color into it.

**Status dot.** A granted permission or the enabled master switch reads as a filled `signal`-color
dot (or track), never a filled pill. This is the *only* place `signal` appears outside the lookup
card - if a future screen wants the accent for something else, that's a sign the vocabulary is
being diluted.

**Inputs.** Filled, not outlined (round 7 - was `OutlinedTextField`, now a borderless `TextField`
with a `sunken` fill and no focus/unfocus indicator line, matching the shadow-based tile system).
`rounded.md` corners, one line each. Password-style masking on both API-key fields by default,
since both are secrets rendered on a screen a phone's owner might not always be alone with. The
API-key helper text's `aistudio.google.com` mention is a real tap target (round 7) - it opens
`https://aistudio.google.com/apikey` directly rather than making the user type the address.

## Do's and Don'ts

- **Do** keep `signal` (#C4440B / dark #E86A2A) as the only color that means "this is on." If a
  second color starts appearing on interactive/active elements, the hierarchy has broken down.
- **Do** size native-script text (Noto Sans Kannada) larger than the Poppins sizes it sits next to -
  equal point size does not mean equal legibility across scripts.
- **Do** treat the lookup card as a distinct visual language from the settings cards - gradient,
  floating, no persistent chrome - never restyle it to match the flat section cards, and never
  edit its own color/type tokens as part of an app-wide pass; they're intentionally separate.
- **Do** draw a tile's structure with a soft shadow (round 7), not a hairline - `outline` is
  reserved for row-dividers inside a tile and the segmented control's selected-key edge, not for a
  tile's own boundary any more.
- **Don't** add a second filled button to any screen. Hierarchy is one primary action or none.
- **Don't** use `error` on anything but the failure-state text inside the lookup card - it is not
  a general-purpose warning or destructive-action color in this system.
- **Don't** fill a pill/chip with `signal` for anything other than a granted/active status - the
  accent marks state, it doesn't decorate a label.
- **Don't** letter-space body or headline text - `letterSpacing` is reserved for `display-lg` and
  `label-sm`, where it's doing real typographic work, not everywhere by default.
